# حالة مزوّد النماذج

آخر تحديث: **١٤ أغسطس ٢٠٢٦**.

## القاعدة

`OpenAI` هو المزوّد النشط والوحيد في الإنتاج. `Groq` و`Ollama` **موجودان في
الـworkflow وغير محذوفين**، لكن `disabled: true` على كل عقدهما، ولا يدخلان أي
مسار تنفيذي. تفعيل أيٍّ منهما قرار يدوي صريح — لا يوجد `needsFallback` مفعّل
في أي مكان، فلا failover تلقائي.

## الوضع الحالي

| العقدة | النموذج | الحالة |
|---|---|---|
| OpenAI — المنسّق | `gpt-4o-mini` | **مفعّل** |
| OpenAI — المتخصصون | `gpt-4o` | **مفعّل** |
| OpenAI — المستندات | `gpt-4o` | **مفعّل** |
| Groq — المنسّق | `openai/gpt-oss-20b` | معطّل — standby |
| Groq — المتخصصون | `openai/gpt-oss-120b` | معطّل — standby |
| Groq — المستندات | `openai/gpt-oss-120b` | معطّل — standby |
| Ollama — المنسّق | `qwen3-vl:30b-a3b-instruct-q4_K_M` | معطّل — standby |
| Ollama — المتخصصون | نفسه | معطّل — standby |
| Ollama — المستندات | نفسه | معطّل — standby |

| المتغيّر | القيمة الافتراضية |
|---|---|
| `ACMS_AGENT_PROVIDER` | `openai` |
| `ACMS_DOC_PROVIDER` | `openai` |
| `ACMS_AGENT_FALLBACK` | لا أثر له — الاحتياطي مشروط بـ`PROVIDER == "groq"` |
| `ACMS_DOC_FALLBACK` | نفس الشيء |
| `ACMS_STRUCTURED` | `0` — المخرجات المهيكلة تُنشر كتغيير مستقل |
| `ACMS_OPENAI_CRED_ID` | id الـcredential في n8n |

`needsFallback` = `false` على المنسّق والمتخصصين الستة ووكيل المستندات.

## الاعتماد (credential)

مفتاح OpenAI **لا يوجد في هذا المستودع ولا يمرّ عبر البناء**. يُنشأ في واجهة
n8n، والبناء يقرأ id فقط:

```bash
docker exec n8n-n8n-1 node -e "
const fs=require('fs');
for (const s of ['','-wal','-shm']) { try{ fs.copyFileSync('/home/node/.n8n/database.sqlite'+s,'/tmp/c.sqlite'+s);}catch(e){} }
const {DatabaseSync}=require('node:sqlite');
console.log(new DatabaseSync('/tmp/c.sqlite')
  .prepare(\"select id,name from credentials_entity where type='openAiApi'\").all());
"
```

ثم يُبنى بذلك الـid:

```bash
cd ~/acms-agent/n8n   # أو D:\Cloude\acms-agent\n8n
ACMS_OPENAI_CRED_ID=<id> python3 build_agent.py
```

## أمر النشر

```bash
docker exec n8n-n8n-1 n8n export:workflow --id=acmsOrch01 \
  --output=/tmp/bk.json && docker cp n8n-n8n-1:/tmp/bk.json \
  ~/wf-backups/acmsOrch01.$(date +%Y%m%d-%H%M%S)-pre-openai.json
docker cp workflows/acmsOrch01.json n8n-n8n-1:/home/node/acmsOrch01.json
docker exec n8n-n8n-1 n8n import:workflow --input=/home/node/acmsOrch01.json
docker exec n8n-n8n-1 n8n update:workflow --id=acmsOrch01 --active=true
docker restart n8n-n8n-1
```

`import:workflow` يصفّر `active`، فخطوة `update:workflow` وإعادة التشغيل
إلزاميتان. إعادة التشغيل تقطع ~15 workflow أخرى (بوتات تيليجرام) لنحو ٣٠ ثانية.

## التحقّق بعد النشر

```bash
python3 -c "import json;w=json.load(open('workflows/acmsOrch01.json'));
print([(n['name'], bool(n.get('disabled'))) for n in w['nodes'] if 'lmChat' in n['type']])"
```

يجب أن يُظهر عقدة مفعّلة **واحدة فقط** لكل مستهلك. البناء نفسه يطبع هذا الجدول
في نهايته، فلا حاجة للثقة في الثوابت.

## الرجوع إلى Groq

```bash
ACMS_AGENT_PROVIDER=groq ACMS_DOC_PROVIDER=groq python3 build_agent.py
```

## توجيه النماذج حسب المهمة (١٤ أغسطس ٢٠٢٦)

المتخصصون وحدهم موجَّهون. المنسّق يعمل بالنموذج الرخيص أصلًا ولا يفعل غير
التوزيع، والمستند نداء ضخم واحد يحتاج النموذج الكبير دائمًا — فلا معنى لتوجيه
أيٍّ منهما.

القرار يُتَّخذ في `Approval Gate` من النية التي يحسبها موجّه النية أصلًا، فلا
تصنيف إضافي ولا نداء نموذج: القرار موجود قبل الوصول إلى أي نموذج. الجدول في
`SPEC_MODEL_ROUTES` أعلى `build_agent.py`، وكل نية غير مذكورة تسقط على النموذج
الكبير — وهو الاتجاه الآمن للخطأ.

| النية | النموذج |
|---|---|
| `pipeline_question` | `gpt-4o-mini` |
| ما عداها | `gpt-4o` |

عقدة «OpenAI — المتخصصون» تقرأ القرار بتعبير `mode: id`، ويتكرّر النموذج
الافتراضي داخل التعبير نفسه حتى لا ينتج عنه اسم فارغ لو رجعت البوابة بلا قيمة.

مُقاس على الجولة المرجعية: **بلا أي ارتداد** (12 PASS / 1 FAIL كما قبله)، و**6
من 18 تنفيذًا (33%) على النموذج الخفيف**، و**21% من التوكنز**. عدد التوكنز نفسه
لا يتغيّر بالتوجيه — المكسب في سعر الوحدة لا في الكمية، فلا تقِس هذا التغيير
بعدّ التوكنز.

**نتيجة لازمة:** لم يعد زوج أسعار واحد يصف الجولة. `harvest.js` صار يسجّل
`specModel` لكل تنفيذ، لأن n8n لا يخزّن اسم النموذج بجوار الاستهلاك — أسماء
العقد فقط — فقرار البوابة هو المكان الوحيد الذي يمكن استرجاعه منه لاحقًا.

## المخرجات المهيكلة — مُفعَّلة (`ACMS_STRUCTURED=1`، ١٤ أغسطس ٢٠٢٦)

نُشرت في محاولتين. الأولى رُجِّعت في اليوم نفسه، والثانية هي القائمة.

### ما كسر المحاولة الأولى

كان المخطط يُلزم حقل `evidence`. النتيجة أن الفشل **انتقل** ولم يقلّ:

- اختبار 18 نجح ← فشل: عند طلب إنشاء فرصة لحساب غير موجود، **اختلق كود السند**
  وذكر `ACC-2026-000007` (وهو Vodafone)، وأصدر اقتراحًا بمعرّفه، وادّعى التنفيذ.
- اختبار 3 فشل ← نجح، لكن الردّ الصحيح ذُيِّل بـ«الإجابة بلا سند من النظام»
  لأن `evidence` رجع **فارغًا على إجابة مُسنَدة فعلًا**.

**حقل إلزامي بلا قيمة صحيحة لا يُنتج إسنادًا، بل شيئًا يشبهه.**

### ما تغيّر في الثانية

1. **`evidence` خرج من المخطط بالكامل.** المطلوب `answer` فقط، والاختياري
   `risks` و`recommendations` و`limitations` و`action_required`. السند يُلحقه
   النظام بعد الإجابة من **سجل الأدلة** عبر `GET :3025/evidence/{session}` —
   المسارات التي استُدعيت فعلًا وأعداد السجلات والقصّ. النموذج لم يعد يستشهد،
   فلا يستطيع أن يستشهد بما لم يُعطَه.
2. **`typeVersion` للعقد الثلاث = `1.2` لا `1.3`.** على 1.3 يعيد المتخصص —
   حين يجيب بلا نداء أداة — كتل محتوى، فينهار `outputParserStructured` بـ
   `text.trim is not a function`. و`autoFix` عاجز عن إصلاحه لأنه يطلب إعادة
   كتابة الـJSON والـJSON لم يكن المشكلة. الأثر: **كل سؤال استيضاح يتحول إلى
   خطأ عام** — ثلاثة أسئلة، ثلاثة إخفاقات؛ وعلى 1.2 ثلاث إجابات صحيحة.
3. تحقّق الحساب في القائمة البيضاء (القسم السابق) يغلق مسار الاختلاق من جهته.

`autoFix: true` **يتطلب مدخل `ai_languageModel` خاصًّا به** — بدونه يفشل كل
نداء متخصص بـ«A Model sub-node must be connected and enabled» ويظهر للمستخدم
كخطأ وكيل عام. موصول بنموذج المنسّق الأرخص.

### القياس

كل الجولات السبع مُعاد تقييمها تحت الفحوص المصححة: **13 PASS / 0 FAIL**
مع المهيكلة، مقابل 12/1 بدونها. الفارق كله اختبار 3، وهو متقطّع أصلًا
(بدون المهيكلة: نجح مرة من خمس؛ معها: مرتين من مرتين) — مؤشّر لا برهان.

## تحذير عند القراءة لاحقًا

اختبار المخرجات المهيكلة على مزوّد لا يثبت سلوكها على غيره — التزام النموذج
بمخطط JSON يختلف بين النماذج. لهذا `ACMS_STRUCTURED` منفصل عن `PROVIDER`،
وشِقّاه (عقدة المحلّل + قواعد النقل في تعليمات المنسّق) مربوطان بالثابت نفسه
حتى لا يُنشر نصفه.
